# POLICY_CONTACT

Source: MDWEB-700 (MD x CLO TS Integration, 진행 중)

---

## 1. 문의 유형 구조

문의 첫 화면에서 3가지 진입 경로를 구분한다.

| 진입 경로 | 대상 | 비고 |
| --- | --- | --- |
| 일반 문의 (회원) | 로그인 회원 | |
| 일반 문의 (비회원) | 비로그인 사용자 | TS/Bug 관련 옵션 미노출 |
| 기술 지원 (TS) | 로그인 회원 전용 | 비회원 경로에 노출 안 함 |

---

## 2. TS 폼 필드 정의

CLO TS 폼과 동일한 필드·운영 체계 기준. 입력은 최소화.

| 필드 | 필수 여부 | 값 | 비고 |
| --- | --- | --- | --- |
| OS | 필수 | Windows / macOS | 설명 본문이 아닌 별도 필드로 전달 |
| MD 버전 | 필수 | 텍스트 입력 | |
| 답변 수신 이메일 | 필수 | 이메일 입력 | 「내 이메일 사용」 시 로그인 계정 이메일 자동 입력 |
| 문의 내용 | 필수 | 텍스트 입력 | |
| 미국/인도 주소 등 BD용 필드 | 선택 | - | MD에서는 비어 보낼 수 있음 |
| 오피스 | 제외 | - | MD에서는 이번 범위 제외 |

---

## 3. Bug Report vs Technical Issues

사용자에게 Bug Report / Technical Issues를 분리하지 않는다.
**하나의 기술 지원(Tech Support)** 카테고리로 통합 수신 후 내부에서 판단.

---

## 4. 브랜드·유입 구분

| 항목 | 정책 |
| --- | --- |
| Product Type (MD/CLO 구분) | 사용자 선택 UI 없음. 내부에서만 설정 (Zendesk 처리) |
| 유저 타입 | MD/CLO 공통 필드 체계 적용. Small Business ↔ 화면 Indie 등 표기/저장 분리는 별도 합의 후 반영 |

---

## 5. 미확정 항목 (별도 합의 후 반영)

- 유저 타입 공통 옵션 최종안
- Indie를 선택지로 둘지 여부
- Product Type 저장 규칙
