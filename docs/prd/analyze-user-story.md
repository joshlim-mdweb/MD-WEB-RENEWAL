## Epic

설문 제작자가 응답 데이터에서 실행 가능한 인사이트를 발견하고, 그것을 한 문장으로 정리해서 공유할 수 있게 한다.

---

## 유저 페르소나

### 페르소나 A — 사이드 프로젝트 리서처

스타트업 기획자나 대학원생. 본인이 직접 설문을 만들고 지인 네트워크에 배포했다. 응답 50~200개. 목적: "이 데이터로 의사결정을 뒷받침하거나 발표 자료를 만들고 싶다." 기술 수준 중간. 엑셀로 직접 집계하는 수고를 피하고 싶다.

### 페르소나 B — 소규모 팀 PO/PM

사내 설문(팀 만족도, 기능 수요 파악)을 정기적으로 돌린다. 응답 30~100개. 목적: "경영진에게 한 줄 요약을 보내야 한다. 가장 눈에 띄는 패턴이 무엇인지 빠르게 파악하고 싶다." 시간이 없다.

### 페르소나 C — 크리에이터·강사

팔로워 대상 취향·수요 조사를 불규칙하게 운영한다. 응답 20~500개. 목적: "팔로워들이 실제로 어떻게 생각하는지, 특정 그룹(예: 2030 vs 4050)이 어떻게 다른지 알고 싶다." 분석 경험 낮음. 숫자보다 "이야기"를 원한다.

---

## 유저 스토리 — 시간 순서

### 1단계 — 마감 알림: "이제 결과를 봐야지"

**상황**  
설문 마감 시점 또는 직접 마감 처리 직후. 제작자는 My Page 또는 설문 목록에 있다. 설문 카드의 상태 배지가 "진행 중"에서 "마감됨"으로 바뀐 것을 확인한다.

**행동**  
설문 카드의 "결과 보기" 버튼을 클릭한다. (페르소나 B는 마감 완료 알림 이메일 / 인앱 알림에서 직접 링크를 타고 들어올 수도 있다.)

**기대**  
리포트 페이지(`/survey/[id]/report`)로 진입하면서 응답 현황이 바로 보인다.

**감정**  
기대감. "얼마나 응답이 왔을까?" 숫자가 적으면 약간의 실망, 많으면 설렘.

---

### 2단계 — 전체 개요 파악: "몇 명이 응답했고, 뭘 가장 많이 골랐지?"

**상황**  
리포트 페이지 상단 요약 섹션. 총 응답 수, 설문 기간, 평균 완료 시간(추후)이 보인다. 아래로 스크롤하면 질문별 분포 차트가 나열된다.

**행동**  
페이지를 위에서 아래로 훑는다. 각 질문 카드에서 가장 많이 선택된 항목(ACCENT 색상 강조)을 확인한다.

**기대**  
한 번 훑는 것만으로 "전체 응답의 큰 그림"이 보여야 한다. 불필요한 클릭 없이.

**감정**  
페르소나 B: "이 정도면 발표 자료로 쓸 수 있겠다." / 페르소나 A: "뭔가 더 파봐야 할 것 같다."

---

### 3단계 — Key Sentence 자동 생성: "이 결과를 한 문장으로 요약하면?"

**상황**  
리포트 상단, 응답 수 요약 바로 아래에 Key Sentence 카드가 있다. 처음에는 "핵심 문장을 생성하는 중이에요..." 상태로 보인다. 2~3초 내로 문장이 채워진다.

**행동**  
Key Sentence를 읽는다. 마음에 들면 "복사하기"를 누른다. 마음에 들지 않으면 "다시 생성하기" 또는 직접 편집한다.

**기대**  
"20대 응답자의 67%가 가격을 최우선으로 꼽았다"처럼 구체적인 수치와 패턴이 담긴 문장. 단순히 "응답자들이 가격을 중요하게 생각했다"는 수준이면 안 된다.

**Key Sentence 생성 방식 — 결정 사항:**

규칙 기반(MVP)과 AI 생성(Phase 2)을 분리한다.

MVP — 규칙 기반 자동 생성:

- 가장 높은 응답률을 보인 선택형 질문 1개를 선택한다.
- 해당 질문의 1위 선택지와 비율을 추출한다.
- 고정 템플릿에 대입한다: `"응답자 {N}명 중 {X}%가 '{선택지}'를 선택했어요"`
- 단답/서술 질문만 있는 경우: "응답 {N}개가 수집됐어요. 직접 답변을 확인해 보세요"

Phase 2 — AI 생성 (Pro 이상):

- 모든 질문의 집계 데이터를 컨텍스트로 AI에 전달한다.
- 포트폴리오 제목처럼 쓸 수 있는 구체적 수치 포함 문장을 생성한다.
- 크레딧 소비 (monetization.md 기준: 80 크레딧 / 생성 1회).
- 사용자가 편집 후 저장할 수 있다.

**감정**  
"오, 이걸 바로 카카오톡에 공유할 수 있겠다." (페르소나 C)

---

### 4단계 — 특정 질문 선택: "이 질문 결과를 더 자세히 보고 싶다"

**상황**  
질문 카드 목록을 스크롤하다가 특정 질문의 분포가 궁금해진다. 예: "가격 vs 품질 질문에서 분포가 51:49로 갈렸다 — 어떤 그룹이 가격을 더 중시할까?"

**행동**  
질문 카드에 마우스를 올리면 우상단에 "분석하기" 버튼이 나타난다. 클릭.

**기대**  
해당 질문을 대상으로 하는 분석 패널이 하단에서 슬라이드업된다. 전체 응답 분포 차트가 즉시 보인다.

**감정**  
"이 버튼이 뭘 해주는 건지 바로 알겠다."

---

### 5단계 — 분석 유형 선택: "어떤 방식으로 분석할까?"

**상황**  
분석 패널이 열렸다. 패널 상단에 탭이나 선택 버튼으로 분석 유형을 선택할 수 있다. MVP에서는 두 가지: "기본 분포" (기본 선택) / "교차 분석".

**행동**  
"기본 분포"는 이미 차트로 보이고 있다. "교차 분석" 탭을 클릭하면 조건 설정 UI가 나타난다.

**기대**  
분석 유형 전환이 페이지 이동 없이 패널 내에서 즉시 전환된다.

---

### 6단계 — 교차 분석 조건 설정: "특정 그룹만 보고 싶다"

**상황**  
교차 분석 탭 활성 상태. 패널 내에 조건 빌더 UI가 보인다.

**행동**

1. "조건 질문 선택" 드롭다운을 클릭 → 다른 질문들이 목록으로 보인다.
2. 조건으로 쓸 질문을 선택한다 (예: "연령대를 선택해 주세요").
3. "답변 선택" 드롭다운이 활성화 → 선택지 목록이 보인다 (예: "20대", "30대", ...).
4. "20대"를 선택한다.
5. 조건이 확정되고 API 호출이 시작된다.

**기대**  
조건 설정 후 2초 이내에 필터된 결과가 차트로 표시된다. 조건 요약 뱃지 ("연령대 = 20대") 가 패널 상단에 표시된다.

**감정**  
"아, 이게 엑셀 피벗 테이블이랑 비슷한 건데 훨씬 쉽네."

---

### 7단계 — 결과 확인: "인사이트 발견"

**상황**  
필터 적용 결과 차트가 보인다. "전체 150명 중 42명이 이 조건에 해당해요"라는 응답자 수 안내가 보인다.

**행동**  
필터 전 분포와 비교하며 차이를 본다. 20대는 가격을 80% 선택했는데 전체는 51%였다는 걸 발견한다.

**기대**  
차이가 명확하게 보여야 한다. 수치만이 아니라 시각적으로 "많이 다르다"는 게 느껴져야 한다.

**엣지케이스 처리:**

- 조건에 해당하는 응답자가 0명 → "이 조건에 해당하는 응답이 없어요" 빈 상태 표시
- 필터된 응답자가 5명 미만 → 차트 표시 + "응답이 적어 참고용으로만 활용해요" 경고 뱃지

**감정**  
"이걸 발견하려고 설문을 돌린 거였는데!" 만족감.

---

### 8단계 — Key Sentence 수정 및 저장

**상황**  
인사이트를 발견한 후 리포트 상단의 Key Sentence를 업데이트하고 싶다.

**행동**  
Key Sentence 카드의 "편집하기" 버튼을 클릭 → 텍스트 인라인 편집 모드 진입 → 수정 → "저장하기" 클릭.

**기대**  
수정한 Key Sentence가 저장된다. 저장 후 토스트: "핵심 문장을 저장했어요."

**저장 여부 결정:**  
Key Sentence는 `surveys` 테이블에 `key_sentence TEXT` 컬럼을 추가해 저장한다. NULL이면 규칙 기반 자동 생성값을 화면에만 표시한다. 사용자가 저장하면 DB에 기록한다. → opin-be 마이그레이션 필요.

---

### 9단계 — 공유 또는 내보내기

**상황**  
분석이 완료됐다. 이 결과를 팀에 공유하거나 보고서에 넣고 싶다.

**행동 (MVP)**  
리포트 상단 "공유하기" 버튼 → 공개 리포트 링크 복사. (기존 `survey_shares` 토큰 메커니즘 활용 가능)

**행동 (추후)**  
"PNG로 내보내기" → 분석 결과 차트를 이미지로 다운로드.

**기대**  
링크를 받은 사람은 별도 로그인 없이 결과를 볼 수 있다. (응답자 개인 식별 정보 노출 없이)

## 분석 유형 카탈로그

각 분석 유형은 리포트 내에서 카드 또는 탭으로 진입한다.

### 유형 1 — 기본 분포 (Basic Distribution)

이름: 기본 분포  
한 줄 설명: 각 질문에 응답자들이 어떻게 답했는지 전체 분포를 확인해요  
필요한 데이터: 질문별 answers 집계 (현재 구현됨)  
지원 타입: 모든 선택형 질문 (multiple_choice, dropdown, checkbox, scale, grade, ranking)  
MVP 포함: 포함 (이미 구현 — `SurveyReportClient`)  
비고: 현재 리포트 페이지가 이 기능을 한다. 분석 패널 내에서도 재노출.

---

### 유형 2 — 교차 분석 (Cross-tabulation)

이름: 교차 분석  
한 줄 설명: 특정 답변을 선택한 응답자들이 다른 질문에서 어떻게 답했는지 비교해요  
필요한 데이터: 동일 response_id 기준으로 두 질문의 answers를 조인  
지원 타입: 조건 질문 — multiple_choice, dropdown (MVP) / 분석 대상 — multiple_choice, dropdown (MVP)  
MVP 포함: 포함 (상세 설계는 `analyze-feature.md` 참조)  
비고: "20대이면서 가격을 선택한 비율" 같은 인사이트 생성 가능

---

### 유형 3 — 텍스트 응답 뷰어 (Text Response Viewer)

이름: 서술 응답 보기  
한 줄 설명: 단답·서술형 질문의 응답을 한눈에 모아서 읽어요  
필요한 데이터: short_text, long_text 타입 answers (텍스트 목록)  
지원 타입: short_text, long_text  
MVP 포함: 포함 (현재 `SurveyReportClient`에 텍스트 렌더 존재 — 별도 패널 불필요)  
비고: 분석이 아닌 "읽기" 기능. 키워드 분석은 Phase 2 AI 기능.

---

### 유형 4 — 응답 완료율 분석 (Drop-off Analysis)

이름: 이탈 지점 분석  
한 줄 설명: 어떤 질문에서 응답자가 설문을 그만뒀는지 파악해요  
필요한 데이터: 각 질문별 answer 수 vs 전체 response 수 비교  
지원 타입: 전체 질문 (endpoint 포함)  
MVP 포함: 미포함 (Phase 2)  
비고: 설문 설계 개선을 위한 데이터. 응답 100개 이상일 때 의미가 있음.

---

### 유형 5 — AI 인사이트 생성 (AI Insight)

이름: AI 인사이트  
한 줄 설명: 전체 응답 데이터를 AI가 분석해서 주요 패턴과 제안을 알려줘요  
필요한 데이터: 모든 질문의 집계 결과 + 응답 원본 (텍스트 포함)  
지원 타입: 전체 (단 텍스트 응답 포함 시 더 풍부한 결과)  
MVP 포함: 미포함 (Phase 2 — Pro 플랜 이상, 크레딧 소비)  
비고: `monetization.md` 기준 80 크레딧/회. 생성 결과 저장 필요 (재사용).

---

## 핵심 질문 — 결정 사항

### Q1. Key Sentence는 AI가 생성하나, 규칙 기반으로 자동 생성하나, 사용자가 직접 쓰나?

결정: 3단계 분리.

| 단계   | 방식             | 조건                 | 플랜 제한 |
| ------ | ---------------- | -------------------- | --------- |
| MVP    | 규칙 기반 자동   | 선택형 질문 1개 이상 | 전체 플랜 |
| Phase2 | AI 생성 (버튼)   | Pro 이상, 크레딧 80  | Pro / Max |
| 항상   | 사용자 직접 편집 | 항상 가능            | 전체 플랜 |

규칙 기반 MVP 구현: 응답률 최고인 선택형 질문 1위 선택지 + 비율을 고정 템플릿에 대입. DB 저장은 사용자가 "저장하기" 누를 때만 (`surveys.key_sentence` 컬럼 추가 필요).

---

### Q2. 분석은 몇 개 유형까지 MVP에 포함할 것인가?

결정: MVP는 2개.

1. 기본 분포 (이미 구현, 재노출)
2. 교차 분석 (`analyze-feature.md` 기준으로 구현)

텍스트 응답 뷰어는 기존 리포트 페이지에 이미 존재하므로 별도 유형으로 진입점만 정리.  
이탈 지점 분석, AI 인사이트는 Phase 2.

---

### Q3. 분석 결과는 저장되는가?

결정: 교차 분석 결과는 저장하지 않는다 (Phase 2). 이유:

- 교차 분석은 매번 조건을 바꿔가며 탐색하는 행동 패턴이다.
- 저장보다 빠른 재조회가 더 유용하다.
- DB 설계 추가 없이 MVP 출시 가능.

저장하는 것: Key Sentence만 (`surveys.key_sentence` 컬럼).

---

### Q4. 공유 기능은 MVP 범위인가?

결정: 링크 공유는 MVP. PNG 내보내기는 Phase 2.

- 기존 `survey_shares` 토큰 메커니즘을 리포트 공유에 재활용 가능.
- 공유받은 사람이 볼 수 있는 범위: 기본 분포 + Key Sentence. 교차 분석 조건 설정 불가.
- 개인정보: 개별 응답자 식별 정보 노출 없음 (집계 데이터만 공개).

## 엣지케이스

### 응답이 0개인 경우

- 리포트 페이지 진입 가능.
- Key Sentence 자리: "응답이 아직 없어요. 설문을 공유해 보세요" 표시.
- "분석하기" 버튼: 비활성. hover 시 툴팁 "응답이 없어 분석할 수 없어요".
- 교차 분석 진입 차단.

### 응답이 너무 적은 경우 (5명 미만)

- 기본 분포: 차트는 표시. 상단에 "응답이 적어 참고용으로만 활용해요" 안내 뱃지.
- 교차 분석 결과: 필터된 응답자가 5명 미만이면 동일 안내 뱃지. 차트는 표시 (숨기지 않음).
- Key Sentence: "응답이 {N}명으로 적어 신뢰도가 낮을 수 있어요. {선택지} 답변이 가장 많았어요."
- 통계적 유의미 판단은 사용자에게 맡긴다. 시스템은 경고만 한다.

### 텍스트 응답만 있는 경우 (선택형 질문 없음)

- Key Sentence 규칙 기반 생성 불가 → "직접 핵심 문장을 입력해 보세요" + 빈 편집 입력창.
- "분석하기" 버튼: 모든 질문 카드에서 비활성. 전체 분석 패널 진입 불가.
- 교차 분석 탭 자체 숨김 (선택형 질문 없으면 조건 설정 불가).
- 텍스트 응답 뷰어는 정상 표시.

### 질문이 1개뿐인 경우

- 기본 분포: 정상 표시.
- 교차 분석: 조건으로 쓸 다른 질문이 없음 → "분석하기" 버튼은 노출하되, 패널 내 "+ 조건 추가" 비활성. 안내: "조건으로 사용할 다른 질문이 없어요".

## 이벤트 로깅 추가 포인트 (User Story 기반)

`analyze-feature.md`의 이벤트 외 추가:

| 이벤트명                   | 트리거 시점                | 주요 파라미터                        |
| -------------------------- | -------------------------- | ------------------------------------ |
| `report_page_viewed`       | 리포트 페이지 진입         | survey_id, total_responses, status   |
| `key_sentence_viewed`      | Key Sentence 화면에 표시됨 | survey_id, generation_type (rule/ai) |
| `key_sentence_edited`      | 사용자가 편집 모드 진입    | survey_id                            |
| `key_sentence_saved`       | 저장 완료                  | survey_id, is_ai_generated           |
| `key_sentence_copied`      | "복사하기" 클릭            | survey_id                            |
| `report_share_link_copied` | 공유 링크 복사             | survey_id                            |
| `analysis_type_switched`   | 분석 유형 탭 전환          | survey_id, from_type, to_type        |

## CS 문의 발생 가능 지점

1. "핵심 문장이 이상해요" → 규칙 기반 생성 결과 품질 불만. 직접 편집 기능 안내.
2. "분석 결과가 전체 응답 수와 안 맞아요" → 소규모 샘플 경고, 또는 텍스트 응답이 집계에서 제외된 것. 각주 안내 강화.
3. "공유 링크를 받은 사람이 교차 분석을 못 해요" → 공유 뷰는 읽기 전용 기본 분포만 노출. 정책 안내 필요.
4. "저장했는데 Key Sentence가 사라졌어요" → `surveys.key_sentence` 마이그레이션 전 발생 가능. BE 마이그레이션 선행 필수.

## Admin 수동 처리 필요 여부

없음. 리포트 + 분석 기능 전체는 읽기 전용. Key Sentence 저장만 쓰기 발생하나 사용자 본인 데이터에 한정. Admin 개입 불필요.

## 구현 선행 조건 (BE 마이그레이션)

Key Sentence 저장 기능 구현 전에 아래 마이그레이션이 필요하다.

```sql
ALTER TABLE surveys ADD COLUMN key_sentence TEXT;
```

교차 분석 API는 `analyze-feature.md` 5절 참조.
