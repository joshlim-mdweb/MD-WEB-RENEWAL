# 정책 문서 작성 규칙

적용: Slack Canvas 게시본 · `docs/policy/**` · `requirements/**/policy-*.md`
출력 형식: **Markdown** — 복붙 즉시 사용 가능

읽는 사람: BD·영업 · CS · 글로벌팀 · 개발·SW PM. 전원이 판단 근거로 쓰는 문서다.

---

## 최우선 원칙

**정책 문서는 규칙을 진술하는 글이다. 설득하거나 분위기를 만드는 글이 아니다.**

다만 규칙만 끊어 나열하면 문서가 아니라 메모가 된다. 게시본은 **읽히는 문서**여야 한다.
한 문장을 쓸 때마다 묻는다 — **"이건 규칙 진술인가, 아니면 규칙을 대신하는 설명인가."**
규칙을 진술하고 그 결과를 덧붙이는 것은 허용한다. 규칙이 불명확해서 설명으로 때우는 것은 금지한다.

---

## 1. 문서 종류로 결정한다

같은 정책이라도 **어디에 게시하느냐**에 따라 등급이 다르다. 이걸 헷갈리면 원장이 장황해지거나 게시본이 메모처럼 읽힌다.

| | **게시본** (Slack Canvas · Confluence) | **원장** (`docs/policy/**`) |
|---|---|---|
| 읽는 사람 | BD·CS·글로벌팀·개발 전원 | 기획·개발 (참조용) |
| 목적 | 읽고 판단한다 | 찾아보고 대조한다 |
| 섹션 오프닝 | **한 문장 정의 필수** (§2) | 생략 가능 |
| 불릿 | **허용** — §3 기준 적용 | 최소화 |
| 연결 프로즈 | **허용** — 인과·조건은 문장으로 잇는다 | 한 줄 = 한 규칙 |
| 결과 문장 (`이는 ~입니다`) | **허용** (§4) | 생략 |
| 검산 예시 | **임계값·요율에 한해 허용** (§4) | 금지 |
| 표 | 적극 사용 | 적극 사용 |

두 등급이 **공통으로** 지키는 것: 합니다체 · 조건+처리 문형 · 폐지 용어 금지 · 같은 규칙 두 번 쓰지 않기 · 미완성 메모 금지.

이 문서에서 별도 표기가 없는 규칙은 두 등급에 모두 적용된다.

## 2. 문서 구조 — 게시본

### 2.1 모든 섹션은 한 문장 정의로 연다

규칙부터 시작하지 않는다. 이 섹션이 **무엇을 다루는지** 한 문장으로 먼저 말한다.

```
❌ ## 3. Individual
   Individual Annual이 일시납에서 구독으로 전환됩니다.

✅ ## 3. Individual
   Individual은 개인 사용자를 위한 단일 사용자 플랜입니다. 이번 Renewal에서 Annual의 결제 방식이 바뀝니다.
```

문서 최상단도 같다. 제목 다음 줄에 **이 문서가 왜 있는지** 한 문장을 둔다.

### 2.2 개수를 먼저 밝히고 목록을 연다

목록을 예고 없이 던지지 않는다.

```
❌ 아래 항목이 바뀝니다.
✅ 이번 Renewal에서 바뀌는 항목은 5가지입니다. 각 항목의 상세는 해당 섹션에서 다룹니다.
```

### 2.3 헤딩

H2·H3까지만 쓴다. H4 이하가 필요하면 섹션을 나누거나 표로 바꾼다.

### 2.4 문서 말미

관련 문서 링크를 블록으로 모아 둔다. 본문 중간에 흩어 두지 않는다.

## 3. 불릿 · 프로즈 · 표

### 3.1 무엇으로 쓸지 먼저 정한다

```
인과·조건·상태 변화가 있는가?          → 프로즈
  불릿 사이에 "그런데 · 왜냐하면 · 그 다음"이 필요하면 그건 프로즈다

주어가 같은 독립 항목의 나열인가?       → 불릿

3개 이상 대상 × 2개 이상 속성인가?      → 표
```

기간·조건이 맞물려 굴러가는 규칙은 불릿으로 쪼개지 않는다.

```
❌ * 스냅샷은 90일간 보관합니다
   * 재개하면 만료가 연장됩니다
   * 미사용 시 자동 삭제됩니다

✅ 환경 스냅샷은 미사용 기준 최대 90일간 보관합니다. 에이전트가 스냅샷에서 시작하거나 재개할 때마다 만료 기한이 90일 연장됩니다. 90일간 사용되지 않은 스냅샷은 플랜과 무관하게 자동 삭제됩니다.
```

### 3.2 불릿은 2등급 — 한 목록 안에서 섞지 않는다

| 등급 | 형식 | 마침표 | 쓰는 곳 |
|---|---|---|---|
| **A** | 명사구·동사구 조각 (3~9어) | **없음** | 항목·옵션·조건 나열 |
| **B** | `**용어**: 완결 문장.` | **있음** | 용어 정의 · 조건부 규칙 |

```
A등급
* 생성 주체: SW Account를 제외한 모든 Member
* 인원 제한 없음
* 하위 권한 역할 없음

B등급
* **Auto Renew 활성**: 만료일 전 자동 갱신 결제를 진행합니다.
* **Auto Renew 취소**: 잔여 기간 종료 후 갱신하지 않습니다. 기간 내 사용은 유지됩니다.
```

A등급은 두 문장이 되어도 마침표를 붙이지 않는다. B등급은 항상 붙인다.

### 3.3 중첩은 2단까지

부모 불릿은 콜론으로 끝내고, 자식은 A등급 조각으로 쓴다. 3단이 필요하면 표이거나 새 H3다.

```
* Userpool 관리 항목:
    * SW Account 생성
    * SW Account 삭제
    * 이메일 초대
```

### 3.4 번호 목록

순서가 있거나, 앞 문장에서 개수를 밝힌 닫힌 집합에만 쓴다. 순서 없는 나열에 번호를 붙이지 않는다.

### 3.5 표

셀도 A/B 규칙을 따른다 — 조각은 마침표 없이, 완결 문장은 마침표를 붙인다.

예외가 셀을 비대하게 만들면 `*` · `†` 기호를 셀에 넣고 **표 아래 각주**로 뺀다. 표의 스캔 가능성을 지키면서 예외를 빠뜨리지 않는 방법이다.

### 3.6 Slack Canvas 줄바꿈

Canvas는 연속된 줄을 한 문단으로 병합한다. 줄바꿈으로 규칙을 나눌 수 없으므로, 게시본에서 항목을 분리할 때는 `*` 불릿을 쓴다. **한 불릿 = 한 규칙** 원칙은 그대로다.

## 4. 설명 · 근거 · 예시

### 4.1 결과 문장을 붙일 수 있다

규칙을 진술한 뒤, 그것이 사용자에게 무엇을 의미하는지 한 문장 덧붙일 수 있다. BD·CS가 고객에게 설명할 때 이 문장을 그대로 쓴다.

```
✅ 4년 카운터는 Pause·Suspended·Cancelled 중에도 계속 흐릅니다. 이는 구독을 멈춰도 이용 가능 기간이 연장되지 않는다는 뜻입니다.
```

읽는 사람의 잘못된 통념을 교정할 때는 대조형을 쓴다.

```
✅ 사용량은 한도까지 연속적으로 회복되며, 정해진 주기에 초기화되지 않습니다.
```

### 4.2 검산 예시는 임계값·요율에만

임계값, 요율, 두 제한이 맞물리는 규칙에만 예시를 붙인다. `**예시:**` 레이블을 달고 **실제 숫자로 답까지** 계산한다.

```
✅ 새 만료일은 기존 만료일에 1년을 더한 날입니다.
   **예시:** 만료일이 2026-03-01인 라이선스를 전환하면 새 만료일은 2027-03-01입니다.
```

### 4.3 여전히 금지

- 지명·상품명을 나열해 규칙을 대신하기 (규칙만 남긴다)
- 규칙이 불명확해서 예시로 때우기 — **예시 없이 안 읽히면 예시를 붙일 게 아니라 규칙 문장을 다시 쓴다**

```
❌ EU도 카나리아 제도·마데이라·올란드처럼 우편번호로 갈리는 특별 세율 지역이 있습니다.
✅ 유럽을 포함한 일부 국가 및 지역도 국가와 우편번호를 함께 검증합니다.
```

## 5. 부정문 — 기본은 쓰지 않는다

**제공하지 않는 것을 일일이 쓰지 않는다.** 지원하지 않는 결제수단만 해도 수천 개다. 범위를 닫는 문장이 이미 배제를 수행한다.

```
✅ Organization 그룹의 Enterprise 플랜과 Indie 플랜 결제에서만 노출합니다.
   → Academic이 빠졌다는 사실이 이 한 줄에 이미 들어 있다
```

### 5.1 예외 — 읽는 사람이 기대할 근거가 있을 때

아래 두 경우에만 부정문을 쓴다.

| 트리거 | 예 |
|---|---|
| Legacy에 있다가 없어진 것 | 한국은 카드와 PayPal을 사용합니다. Kakao Pay는 Legacy에서 제거됐습니다. |
| 형제 케이스엔 있는데 이 케이스만 없는 것 | Indie는 Seat 추가만 가능합니다. 기간 연장은 제공하지 않습니다. |

### 5.2 부정문을 홀로 두지 않는다

`X는 제공하지 않습니다.`로 끝내면 읽는 사람이 대안을 찾아 헤맨다. **무엇을 대신 쓰는지**를 같은 호흡에 붙인다.

```
❌ 연간에서 월간으로 중도 변경은 제공하지 않습니다.
✅ 연간에서 월간으로 중도 변경은 제공하지 않습니다. 구독을 해지하고 만료 후 월간으로 다시 구매합니다.
```

폐지된 용어는 본문이 아니라 **Appendix 용어 변경 표**에서 `구 용어 | 신 용어 | 바뀐 이유`로 다룬다.

## 6. 용어 정의

새 용어는 **첫 등장에서 굵게 표기하고 같은 문장 안에서 정의**한다. 이후에는 굵게 하지 않는다.

```
✅ **SW Account**는 Organization Owner가 생성하는 라이선스 할당 전용 계정입니다. SW Account는 Web 로그인이 불가합니다.
```

UI 레이블·제품명·플랜명은 한국어 문장 안에서도 영문을 유지한다. 읽는 사람이 실제 화면과 대조해야 하기 때문이다.

```
✅ Team Console의 **Manage Seats**에서 배정을 변경합니다.
```

## 7. 문장 규칙

### 7.1 한 줄 = 한 규칙

규칙이 둘이면 줄을 나눈다. 단 게시본에서 인과로 이어지는 두 문장은 한 문단에 둘 수 있다 (§3.1).

```
❌ 주소 국가가 바뀌면 목록을 교체하고 기존 선택을 초기화합니다.
✅ 주소 국가가 바뀌면 결제수단 목록을 교체합니다. 기존 선택은 초기화합니다.
```

### 7.2 조건 + 처리

주어를 조건으로 세운다. 조건 표현은 `~인 경우` · `~할 때` · `~하면`.
**IF · ELSE · → 화살표 표기 금지.**

```
❌ 우편번호는 전 국가 필수입니다.
✅ 우편번호 체계가 없는 국가는 형식 검증을 수행하지 않습니다.
```

### 7.3 명사구 서술

구어체 동사를 명사구로 올린다.

```
❌ 입력만 받습니다              ✅ 형식 검증을 수행하지 않습니다
❌ 세금을 계산해서 보여줍니다    ✅ 세액을 산출하여 표시합니다
```

### 7.4 말투 — `~합니다`

정책 문서는 `~합니다`. PRD는 `~한다`. 저장 위치가 아니라 문서 타입이 기준이다.
사용자 노출 문구(버튼·에러·토스트)는 이 파일이 아니라 `ux-writing.md`를 따른다.

## 8. 절대 금지 패턴 4개

### 패턴 1 — 강조하거나 반박한다

```
❌ 우편번호는 전 국가 필수입니다. 미국만이 아닙니다.
❌ 사용자가 고르지 않고, 시스템이 판정합니다.

✅ 우편번호가 세금 계산에 활용되는 국가는 국가와 우편번호를 함께 검증합니다.
✅ 선택한 계정의 라이선스 상태에 따라 처리 방식을 판정합니다.
```

읽는 사람의 오해를 미리 교정하려 들지 않는다. 규칙이 정확하면 오해가 생기지 않는다.
단 §4.1의 대조형(`A이며, B가 아닙니다`)은 통념 교정 목적일 때 허용한다.

### 패턴 2 — 미완성 문장 · 메모를 남긴다

```
❌ 이 부분은 추후 확인 / (수정 예정)
✅ *(정책 확인 필요)* · *(개발 확인 필요)* · *(협의 필요)*
```

### 패턴 3 — 같은 규칙을 두 번 쓴다 ★

한 번 진술한 규칙을 다른 말로 풀어 쓰지 않는다.

```
❌ 입력은 선택사항입니다. 입력하지 않아도 결제를 진행할 수 있습니다.
✅ 입력은 선택사항입니다.

❌ 추가한 Seat의 만료일은 기존 라이선스와 같습니다.
   한 라이선스의 모든 Seat가 같은 날 만료됩니다.
✅ 추가한 Seat는 기존 라이선스와 같은 날 만료됩니다.
```

풀어 쓰고 싶어지는 것은 규칙 문장이 불안하다는 신호다. 문장을 하나 더 쓰지 말고 원래 문장을 다시 쓴다.

다른 절이나 표에 이미 있는 값을 본문에서 반복하지 않는다. 같은 값이 두 곳에 있으면 한쪽만 고쳐지는 사고가 난다.

### 패턴 4 — 제목이 말한 것을 본문이 다시 말한다

```
❌ ## Seat 추가
   Seat를 추가하는 경우의 규칙입니다. Seat를 추가하면...
✅ ## Seat 추가
   기존 라이선스 만료일까지 남은 기간을 일할 계산해 청구합니다.
```
