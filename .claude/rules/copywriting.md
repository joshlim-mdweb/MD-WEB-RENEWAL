## 핵심 원칙

### 금지 어미

| 금지 | 이유 |
|------|------|
| `~한다` | 딱딱한 서술체 |
| `~합니다` / `~됩니다` | 합쇼체 |
| `~입니다` / `~이에요` | UX Writing 말투 (마케팅 카피에 부적합) |
| `~그게 전부` / `~바로` 같은 수사적 마무리 | 진부한 마케팅 클리셰 |

### 확정 말투

- **명사형 종결**: 문장을 명사 또는 명사구로 끝냄
- **동사 생략형**: 서술어 없이 마무리 (`~으로.` `~까지.` `~대로.` `~없이.`)
- **쉼표 호흡**: 긴 문장은 쉼표로 분리해 리듬감 부여
- **나열형**: 기술 스펙은 쉼표 나열 (`FBX, Alembic, OBJ`)

## 콘텐츠 원칙

### 구체적 기능 묘사 필수

추상적 감성 카피 금지. MD가 실제로 **무엇을 구현하는지** 기술 언어로 서술.

```
❌ "소재마다 반응이 다르다"       ← 추상적
✅ "소재별 무게, 탄성, 마찰 계수 설정으로 각 소재 고유의 텍스쳐와 움직임 구현"  ← 구체적
```

### 결과 언어 우선

기술 설명보다 사용자가 얻는 결과를 앞세움.

```
❌ "물리 엔진이 시뮬레이션을 처리합니다"
✅ "자연스러운 주름과 흐름이 자동으로"
```

### 헤드라인 구조

- 짧고 선언적. 10단어 이내.
- 대비 구조 효과적: `"실크는 흘러내리고, 데님은 버틴다."`
- 쉼표로 끊어 두 개의 이미지 병치
