## 2. 전략적 메시지 원칙

### 2.1 유저 인식 전제
**MD를 처음 접하는 사람을 위한 설명은 하지 않는다.**
우리 사용자는 이미 Marvelous Designer를 알고 온다. "MD가 무엇인지"가 아니라 "왜 지금 MD여야 하는지"를 말해야 한다.

### 2.2 기술 장점 — 1개만, 명확하게
**패턴 기반 물리 시뮬레이션** — 실제 재단 패턴으로 의상을 구성하고 물성(중력, 마찰, 탄성)을 그대로 시뮬레이션하는 방식. 이것이 MD가 다른 툴과 다른 유일한 기술적 차별점이다.

> 이 장점은 모든 페이지에서 한 번씩 언급하되, 기술 설명이 아닌 결과 언어로 표현한다.
> "패턴으로 만들기 때문에 실제 의상처럼 움직인다" 수준으로.

### 2.3 시장성 — 핵심 3가지
페르소나별로 조합을 다르게 쓴다.

| 시장성 축 | 메시지 방향 | 주요 페르소나 |
|---|---|---|
| **Industry Standard** | 대형 게임사·VFX 스튜디오·패션 하우스에서 쓰는 툴. 이력서에 올리는 순간 달라진다. | Personal, Students |
| **커리어 연결** | 배운 것이 포트폴리오로, 포트폴리오가 취업으로. 실무에서 쓰는 툴을 지금 쓰고 있다는 것. | Students |
| **CONNECT 에셋** | MD CONNECT에서 의상 에셋을 바로 가져다 쓸 수 있다. 처음 시작하는 부담을 줄인다. | Personal, Students |

### 2.4 카피 작성 원칙
- 기능이 아닌 **사용자 가치** 중심
- 헤드라인 짧고 명확하게, 설명은 1~2문장
- Core 블록 구조: **Title + Description**
- `~해요` 체 지양 → 자신감 있고 세련된 프로덕트 마케팅 톤
- 문장 종결 혼용: `~입니다` `~할 수 있습니다` `~에 적합합니다` `~도움이 됩니다`

## 3. Personal Designers

### 페이지 목적
**대부분이 프리랜서다.** 스튜디오 소속이 아닌 개인 작업자 — 프리랜서 3D 아티스트, 독립 패션 디자이너, 개인 크리에이터.
이들에게 필요한 건 "더 나은 결과물"이 아니라 "클라이언트에게 납품 가능한 결과물을 더 빠르게, 혼자서".
MD가 프리랜서의 생산성과 수주 경쟁력을 높인다는 방향으로 메시지를 잡는다.

### 페르소나 키워드
freelancer · client delivery · project turnaround · solo workflow · industry-standard output ·납품 가능한 결과물 · 수주 경쟁력 · CONNECT asset · quick start · portfolio · real project · compatible with client pipeline

### 타겟 유저
| 도메인 | 그룹 | 핵심 니즈 |
|---|---|---|
| Game / VFX | 프리랜서 3D 아티스트 | 클라이언트 납품 품질, 빠른 프로젝트 회전, 엔진 파이프라인 호환 |
| Fashion / Apparel | 독립 패션 디자이너 | 샘플 비용 없이 디지털 검토, 클라이언트 프레젠테이션 |
| Virtual Fashion / Metaverse | 버추얼 크리에이터 | 마켓플레이스 판매용 에셋, SNS 콘텐츠 |
| Animation / Film | 독립 애니메이터 | 캐릭터 의상 리깅·시뮬레이션 |
| Architecture / Product Viz | 비주얼라이제이션 아티스트 | 패브릭·소재 표현, 제품 렌더링 |

> 도메인이 다양하더라도 핵심 메시지는 동일하다: "혼자서도 스튜디오 수준의 결과물"

### Core 블록
| Core | 주제 | 핵심 메시지 |
|---|---|---|
| Core 1 | Industry Standard | 대형 스튜디오·게임사·패션 하우스가 쓰는 툴. 실무에서 통하는 결과물. |
| Core 2 | 기술 차별점 (1개) | 패턴 기반 물리 시뮬레이션 — 실제 의상처럼 움직이는 이유 |
| Core 3 | CONNECT + 쉬운 시작 | MD CONNECT에서 에셋 바로 가져다 시작. 처음부터 결과물이 나온다. |

### Hero 방향
```
Title: 혼자서도, 스튜디오 수준의 결과물

Description: 게임, 패션, VFX, 버추얼 패션 — 도메인에 관계없이.
MD CONNECT 에셋으로 바로 시작하고, 대형 스튜디오와 같은 툴로 클라이언트 납품까지.
```

### Workflow: CONNECT 에셋 → Pattern / Simulation → Detail → Export → Portfolio → 실무 프로젝트

### Trial 정책: 14일 무료 → 종료 후 자동 Subscription 시작

## 4. Enterprise

### 페이지 목적
팀·스튜디오·조직 단위 사용자 대상. 효율적 팀 운영, 안정적 파이프라인 연결, 자동화, 확장 가능한 제작 구조, 중앙화된 라이선스·계정 관리를 전달.

**Indie 플랜은 Enterprise 페이지 내 배너로 통합** (별도 Solutions 항목 없음).
Enterprise 인증 후 특가로 제공되는 구조임을 명시.

### 페르소나 키워드
team operation · account management · license management · pipeline · workflow · automation · integration · scalability · stability · technical support · onboarding · studio scale · centralized management · team productivity

### 타겟 유저
| 그룹 | 핵심 니즈 |
|---|---|
| Game Studios | 캐릭터 의상 제작, AAA 파이프라인, 엔진 연결 |
| VFX / Animation Studios | 씬 단위 의상 시뮬레이션, DCC 툴 통합 |
| Pipeline / Technical Teams | Python·REST API 자동화, 내부 시스템 통합 |
| IT / License Admins | 사용자·라이선스·기기 관리, 사용 현황 파악 |

### Core 블록 (6개 — 3열 2행 그리드)

| # | 주제 | 타이틀 | 설명 |
|---|---|---|---|
| 1 | Industry Standard | 도메인에 관계없이 최상위 스튜디오의 공통 선택 | 한 팀에서 검증된 워크플로우가 조직 전체에 그대로 적용됩니다. |
| 2 | Userpool | 프로젝트가 끝나면 라이선스를 다른 팀원에게 옮길 수 있습니다 | 사용하지 않는 라이선스가 그대로 남지 않습니다. 필요할 때 늘리고, 시즌이 끝나면 줄입니다. |
| 3 | 파이프라인 통합 | Maya, Houdini, Unreal Engine — 기존 툴 옆에 바로 연결됩니다 | 파이프라인을 바꾸지 않아도 됩니다. |
| 4 | 중앙화된 관리 | 팀원·기기·라이선스를 한 화면에서 파악할 수 있습니다 | 누가 어떤 기기에서 사용 중인지 관리자 화면에서 바로 확인됩니다. |
| 5 | Scalability | 팀이 10명이든 100명이든 같은 방식으로 운영됩니다 | 규모가 커져도 워크플로우를 새로 짜지 않아도 됩니다. |
| 6 | 기술 지원 | 도입부터 운영까지 전담 기술 지원이 함께합니다 | 팀 온보딩, 파이프라인 셋업, 기술 문의까지 전담 팀이 지원합니다. |

### Hero 방향
```
Title: 스튜디오가 선택한 의상 제작 표준

Description: 업계 주요 스튜디오가 프로덕션에서 사용하는 툴.
팀 단위 라이선스 관리부터 파이프라인 통합까지, 제작 환경에 맞게 구성할 수 있습니다.
```

### Userpool 핵심 메시지
- "프로젝트가 끝나면 다른 팀원에게 재할당" — 낭비 없는 라이선스 운영
- "기간별 할당으로 시즌·스프린트에 맞게 조정" — 유연한 인력 배치
- Enterprise 페이지에서 Userpool을 별도 섹션 또는 Core 2 내 feature로 강조

### Trial 정책: 자동 Trial 없음. 문의를 통해 결정.
