# PRD Writing Style

PRD, 기획서, 회의록 등 요구사항 문서 전체에 적용.

---

## 1. 기본 문체

| 상황 | 형태 | 예시 |
|---|---|---|
| 본문 서술 | `~한다` | "사용자는 파일을 업로드한다." |
| 항목·레이블·제목 | 명사형 | "파일 업로드", "인증 신청 제출", "~를 유지" |
| 조건·정책 설명 | `~한다` | "승인 후 1주 이내 구매한다." |

### 금지

- `~합니다` / `~입니다` / `~됩니다` — 합쇼체 전면 금지
- `~하기로 한다` — 회의록 투. `~한다`로 통일
- `~의 경우` — `~하면`, `~일 때`로 대체
- `확인 바랍니다` — `확인한다`
- `추후 논의` — `(미정)` 또는 `(논의 필요)`
- `진행 예정입니다` — `진행 예정`

```
❌ "활성 라이센스를 유지합니다"
✅ "활성 라이센스를 유지"

❌ "인증 신청 후 상태를 확인할 수 있습니다"
✅ "인증 신청 후 상태를 확인한다"

❌ "추후 논의 예정입니다"
✅ "(논의 필요)"
```

---

## 2. 문서 구조

PRD 필수 섹션 순서:

```
1. Agenda      — TITLE / DESCRIPTION / 요청자 / DUE DATE
2. Background  — 배경 및 도입 이유
3. Requirements — 기능 명세 테이블
4. Scope       — Web / Admin / 기타 영역 구분
5. Flow        — Actor × Step × Description 테이블
6. Action Item — 영역별 실행 항목
7. Impact      — 정량 지표
```

섹션 번호는 숫자로 고정 (`1.`, `2.`, `4.1`, `4.2`). H2/H3 혼용 금지 — 번호 체계로 통일.

---

## 3. Requirements 테이블

```
| 기능명 | Description |
|---|---|
| 파일 업로드 | 사용자는 증빙 서류를 업로드한다. |
| 인증 상태 확인 | 사용자는 상태를 Pending / Confirmed / Rejected로 확인한다. |
```

- **기능명**: 명사형. 동사 없음 — "업로드 하기" (❌) → "파일 업로드" (✅)
- **Description**: `사용자는 / 시스템은 + ~한다` 형식 고정

---

## 4. Flow 테이블

```
| Step | Actor  | Description                          |
|------|--------|--------------------------------------|
| 1    | 사용자 | 인증 신청을 제출한다.                  |
| 2    | System | 상태를 Pending으로 설정한다.           |
| 3    | BD     | 제출된 정보를 검토한다.                |
```

- **Actor**: 한국어 역할명 또는 `System` (영문 고정)
- **상태값**: 영문 고정 — `Pending` / `Confirmed` / `Rejected` / `Active` / `Expired`
- **Description**: `~한다` 형식

---

## 5. Scope 섹션

영역별 번호 소제목으로 구분:

```
4.1 Web
4.2 Admin
4.3 Email Communication Management
```

하위 항목: 불릿 리스트, `~한다` 또는 명사형 통일.

---

## 6. 문서 제목 네이밍

PRD 제목 앞에 대상 영역 태그를 붙인다.

| 태그 | 대상 | 예시 |
|---|---|---|
| `[MD\|SITE]` | 사용자 대면 웹사이트 (marvelousdesigner.com) | `[MD\|SITE] New Feature 페이지` |
| `[MD\|ADMIN]` | 내부 관리자 툴 (CLOver Admin 등) | `[MD\|ADMIN] SW Release UX 개선` |

파일명에도 동일하게 적용: `[MD-SITE]-feature-name.md` / `[MD-ADMIN]-feature-name.md`

---

## 7. 메타 헤더 (문서 상단 필수)

모든 PRD 문서 제목 바로 아래에 한 줄 메타 블록을 작성한다.

```
Epic Key: `{KEY}` | 요청: {이름 또는 팀} | 출처: {Slack 링크 / Jira / 회의} | 작성일: {YYYY-MM-DD}
```

- **요청**: 개인이면 이름(`Jeongsu Lim`), 팀이면 팀명(`SW QA팀`), 불명확하면 `(미정)`
- **출처**: Slack 스레드 링크, Jira 이슈 키, 또는 회의명 중 하나
- **작성일**: 문서 최초 작성일 (수정일 아님)

메타 헤더 바로 아래에 `## 배경` 섹션을 반드시 작성한다. 배경 없는 PRD는 불완전한 문서로 간주한다.

```
## 배경

[왜 이 작업이 필요한지 — 문제 상황, 발생 경위, 이전 작업과의 연결]
```

- 1~3문장으로 간결하게
- "~됐다" / "~남았다" 형식 (`~한다` 체 유지)
- 단순 기능 나열 금지 — 맥락과 이유를 담는다

---

## 7. 표기 규칙

| 기호 | 용도 | 예시 |
|---|---|---|
| `→` | 흐름·전환 | "영상 시청 → 퀴즈 풀이로 검증" |
| `/` | 대안·OR | "MyPage / Catalog list / Detail" |
| `(미정)` | 미결정 항목 | "(미정) 완료자 리스트" |
| `(논의 필요)` | 결정 필요 | "(플로우 논의 필요)" |
| `@이름` | 담당자 지정 | "@Kayden Choi" |
| `~` | 기간 범위 | "09/16~17", "10/20 이후" |
