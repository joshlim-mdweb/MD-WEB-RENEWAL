# MD Web — UX Writing Rules

모든 사용자 노출 텍스트에 적용. 버튼·에러·토스트·모달·빈 상태·안내 문구·플레이스홀더 전부 해당.

2026-05-28 확정.

---

## 1. Core Tone & Voice

- **명확함 > 영리함** — 이해하기 쉬운 문장 우선
- **짧음 > 김** — 한 문장 = 한 행동 or 한 아이디어
- **결과 중심** — "처리했습니다" → "저장했어요"
- **행동 중심** — 다음 행동이 명확하게 드러나야 함
- **감정 과잉 금지** — "죄송합니다" / "감사합니다" / "창의력을 펼쳐보세요" 사용 금지

브랜드 성격: 효율적 · 명확 · 모던 · 신뢰 · 차분. 감정적이거나 과도한 마케팅 톤 금지.

---

## 2. 말투 — 해요체 고정

모든 문구는 `~해요` / `~예요` / `~이에요` / `~돼요`로 끝낸다.
`~합니다` / `~입니다` / `~됩니다` / `~합니다` 절대 사용 금지.

```
✅ "저장했어요"           ❌ "저장됐습니다"
✅ "구독이 취소됐어요"    ❌ "구독이 취소되었습니다"
✅ "처리하고 있어요"      ❌ "처리 중입니다"
```

---

## 3. 문장 스타일

- 짧은 문장. 중첩 절 금지.
- 수동태 → 능동태: "처리됩니다" → "처리돼요"
- 번역투 금지

| 번역투 | 자연스러운 한국어 |
|---|---|
| `~을 통해` | `~로` / `~에서` |
| `~의 경우` | `~하면` / `~할 때` |
| `진행해 주세요` | 구체적 동작 명시 |
| `~시겠어요?` | `~할까요?` |

```
✅ "결제가 완료되면 자동으로 활성화돼요."
✅ "라이선스를 배정해보세요."
❌ "라이선스를 보다 효율적으로 관리할 수 있습니다."
```

## 4. CTA 버튼

- **동사로 시작** + 다음 행동 명확
- 단독으로도 의미가 통해야 함
- 기본 형태: `동사 + 하기`

```
✅ "저장하기" / "라이선스 배정하기" / "플랜 비교하기" / "다시 시도하기"
❌ "시작" / "확인" / "계속" / "제출"
```

**예외**
- 단순 닫기 용도: `"닫기"` 단독 허용
- 다이얼로그 왼쪽(취소) 버튼: 항상 `"닫기"` 고정 — `"취소"` 사용 금지

```
✅ [닫기] [구독 취소하기]
❌ [취소] [구독 취소]
```

**파괴적 액션** — 되돌릴 수 없는 동작은 구체적으로 명시

```
✅ "계정 삭제하기" / "구독 취소하기"
❌ "확인" (위험 동작에 모호한 버튼)
```

**액션 에코 원칙** — 확인 다이얼로그의 오른쪽 버튼은 실행될 액션 동사 그대로

`"확인"` / `"예"` / `"OK"` 단독 금지. 버튼만 봐도 무슨 일이 일어나는지 알아야 한다.

```
✅ "일시정지를 취소할까요?" → [닫기] [일시정지 취소하기]
✅ "구독을 재개할까요?"     → [닫기] [구독 재개하기]
✅ "실행을 취소할까요?"     → [닫기] [실행 취소하기]
❌ "일시정지를 취소할까요?" → [취소] [확인]
```

**버튼별 한국어 규칙**

| 영어 | 한국어 | 비고 |
|---|---|---|
| Close | `닫기` | 모달·시트·다이얼로그 고정 |
| Cancel | `닫기` (흐름 중단) / `구독 취소하기` (파괴적) | `"취소"` 단독 금지 |
| Continue | `다음으로` | `"계속하기"` 금지 — 방향 모호 |
| Skip | `건너뛰기` | |
| Complete / Done | 구체적 동사 우선 (`저장하기` / `결제하기`), 불가 시 `완료하기` | `"확인"` 금지 |
| Confirm | 액션 에코 원칙 적용 | `"확인"` / `"예"` 단독 금지 |
| Submit | `제출하기` | |
| Apply | `적용하기` | |
| Delete | `[목적어] 삭제하기` (목적어 필수) | `"삭제하기"` 단독 금지 |
| Retry | `다시 시도하기` | `"재시도"` 금지 |
| Go back | `뒤로` | |
| Edit / Update | `편집하기` / `수정하기` | 맥락에 따라 선택 |

## 5. 에러 메시지 — 문제 + 해결

에러 메시지의 목적은 **다음으로 나아가도록 안내**하는 것.
기술 용어, 에러 코드 노출 금지. 사용자 탓으로 돌리지 않는다.

```
구조: [무슨 상황인지] + [어떻게 하면 되는지]
```

```
✅ "이메일 형식을 다시 확인해 주세요."
✅ "결제에 실패했어요. 카드 정보를 확인해 주세요."
✅ "일시적인 오류가 생겼어요. 잠시 후 다시 시도해 주세요."
❌ "Invalid request" / "오류가 발생했습니다" / "ERROR: 500"
```

| 상황 | 템플릿 |
|---|---|
| 네트워크·서버 | `"일시적인 오류가 생겼어요. 잠시 후 다시 시도해 주세요."` |
| 입력값 | `"[필드명]을 다시 확인해 주세요."` |
| 권한 부족 | `"[이유]로 이용할 수 없어요. [대안]해 주세요."` |
| 결제 실패 | `"결제에 실패했어요. 카드 정보를 확인해 주세요."` |

## 6. 성공 메시지 (토스트)

- 짧게, 결과만. 과도한 축하 표현 금지.
- 15자 이내 권장

```
✅ "저장됐어요." / "비밀번호를 변경했어요." / "CLO-SET 연결이 해제됐어요."
❌ "성공적으로 저장되었습니다!" / "요청이 정상적으로 처리됐습니다."
```

---

## 7. 빈 상태 (Empty State)

```
구조: [왜 비어있는지] + [어떻게 채울 수 있는지]
```

```
✅ "라이선스가 없어요. 플랜을 구매하면 이용할 수 있어요."
✅ "아직 청구 내역이 없어요."
❌ "데이터가 없습니다" / "No data"
```

---

## 8. 상태별 작성 원칙

| 단계 | 원칙 | 예시 |
|---|---|---|
| 행동 전 | 기대 결과 설명 | "결제 후 바로 사용할 수 있어요." |
| 행동 중 | 진행 상태 | "처리하고 있어요." |
| 행동 후 | 결과 | "저장됐어요." |
| 차단 시 | 해결 방법 | "관리자에게 권한을 요청해 주세요." |

---

## 9. 폼 플레이스홀더

명사형 단독. 긴 문장 금지.

```
✅ "새 닉네임 입력" / "이메일 입력" / "우편번호 입력"
❌ "새 닉네임을 입력해 주세요" (너무 김)
```

## 12. 숫자·날짜 표기

- 금액: `$39.00` / `₩39,000` (천 단위 콤마)
- 날짜: `2026년 1월 1일` / `2026-01-01`
- 기간: `3개월` / `1년`

## 13. 금지 표현 전체 목록

| 금지 | 대체 |
|---|---|
| `~합니다` / `~됩니다` | `~해요` / `~돼요` |
| `~입니다` | `~이에요` / `~예요` |
| `완료되었습니다` | `완료됐어요` |
| `불가합니다` | `할 수 없어요` |
| `재시도` | `다시 시도하기` |
| `로딩 중` | `불러오는 중이에요` |
| `ERROR`, `404`, `500` | 사용자 언어로 풀어쓰기 |
| `~을 통해` | `~로` / `~에서` |
| `~의 경우` | `~하면` / `~할 때` |
| `진행해 주세요` | 구체적 동작 명시 |
| `감사합니다` | 삭제 or 결과 문장으로 대체 |
| `죄송합니다` | 삭제, 해결책 제시 |
| `성공적으로 ~됐습니다` | `~됐어요` |
| `~시겠어요?` | `~할까요?` |
| `계시다` | `있다` |
| `여쭤보다` | `확인하다` |

## 14. MD Web 고정 문구

### 공통 에러
- 네트워크 오류: `"네트워크 연결을 확인하고 다시 시도해 주세요."`
- 서버 오류: `"일시적인 오류가 생겼어요. 잠시 후 다시 시도해 주세요."`
- 결제 오류: `"결제 요청 중 오류가 발생했어요. 잠시 후 다시 시도해 주세요."`

### 구독
- 취소 후: `"현재 구독 기간이 끝날 때까지 계속 이용할 수 있어요."`
- 일시정지 중: `"일시정지 기간 중에는 요금이 청구되지 않아요."`
- 재개 안내: `"구독 재개 전에 알림을 보내 드려요."`

### 계정
- 삭제 경고: `"취소할 수 없는 작업이에요. 계정과 데이터는 30일 후 영구 삭제돼요."`
- CLO-SET 연결 해제: `"CLO-SET 연결이 해제됐어요."`

## 15. Ship 전 체크리스트

- [ ] 3초 안에 이해되는가?
- [ ] 다음 행동이 명확한가?
- [ ] 더 짧게 쓸 수 있는가?
- [ ] 자연스러운 한국어인가?
- [ ] 용어가 일관성 있는가?
- [ ] 감정 과잉 표현이 없는가?
- [ ] 다이얼로그 왼쪽 버튼이 "닫기"인가?
- [ ] 고유명사 영문 유지됐는가?
- [ ] 토스트가 결과만 짧게 담고 있는가?
- [ ] 첫 사용자도 이해할 수 있는가?
