# Marvelous Designer — Writing Rules

적용: 사용자에게 보이는 모든 텍스트 — 버튼 · 에러 · 토스트 · 모달 · 빈 상태 · 안내 문구 · 플레이스홀더 · FAQ · 마케팅 카피

**영문이 원본이다.** KO·ZH-CN·JA는 번역본이다. 원문을 영문으로 먼저 쓰고, 번역 규칙은 `localization.md`를 따른다.

다국어 문구 시트(EN·KO·ZH-CN·JA 4열)를 만들 때도 이 파일이 기준이다. **EN 열이 §1.1을 통과한 뒤에 번역을 시작한다** — 원문이 번역 친화적이지 않으면 나머지 3개 열이 함께 어색해진다. 시트 생성은 `/translate`, 문구 신규 작성은 `/writing`, 출력 전 검수는 `/copy-review`.

문서(PRD·정책서)의 말투는 이 파일이 아니라 `policy-writing.md`와 문서 타입 기준을 따른다.

---

## 0. 우리는 누구에게 말하는가

Marvelous Designer를 쓰는 사람은 대체로 **자기 분야에서 일하는 사람**이다. 게임 스튜디오 캐릭터 아티스트, VFX 하우스 시뮬레이션 담당, 독립 패션 디자이너, 파이프라인 TD.

다만 **모두가 MD 전문가는 아니다.** Maya를 10년 썼지만 MD는 오늘 처음 여는 아티스트, 업계 표준 툴을 배우려는 학생, 샘플 비용을 줄이려고 디지털을 처음 시도하는 패션 브랜드도 우리 사용자다.

그래서 기준은 이 한 줄이다.

> **도메인 지식은 가정하고, 제품 지식은 가정하지 않는다.**

패턴·시뮬레이션·리토폴로지·리깅은 설명하지 않는다. 이미 아는 말이다.
Seat·Organization·SW Account·Student Benefit은 우리가 만든 말이므로 처음 만나는 자리에서 한 번 설명한다.

| 우리는 이렇다 | 우리는 이렇지 않다 |
|---|---|
| 정확하다 | 다정하다 |
| 단호하다 | 조심스럽다 |
| 도메인 지식을 존중한다 | 아는 것을 다시 설명한다 |
| 제품은 처음일 수 있다고 본다 | 우리 용어를 당연하게 던진다 |
| 사실을 말한다 | 분위기를 만든다 |

**소비자 앱의 말투를 따라 하지 않는다.** 친근함을 연출하려는 문장은 이 제품에서 신뢰를 깎는다. 스튜디오 라이선스 담당자가 40 Seat 구매를 확정하는 화면에서 "곧 만나요!" 같은 문장을 읽고 싶어 하지 않는다.

낮춰 보지 않는 것과 안내하지 않는 것은 다르다. 학생에게도 같은 격으로 말하되, 필요한 안내는 빼지 않는다.

## 1. 말투 — 텍스트 종류로 결정한다

화면 위치가 아니라 **텍스트 종류**로 정한다. 이걸 헷갈리는 것이 가장 흔한 실수다.

| 텍스트 종류 | EN | KO |
|---|---|---|
| **마케팅 카피** (Hero · Feature · Solutions) | Title Case 헤드라인 · 단정형 | **명사형 종결** (§3) |
| **사이트 본문** (FAQ · 정책 안내 · 약관) | Sentence case 평서문 | **합니다체** |
| **제품 UI 문구** (토스트 · 에러 · 빈 상태 · 배너) | Sentence case 평서문 | **합니다체** |
| **버튼 · 레이블 · 플레이스홀더** | Title Case 명사구 | **명사형** (§4) |

한 화면에 여러 종류가 섞이는 것은 정상이다. FAQ 본문은 합니다체, 그 안의 버튼은 명사형이다.
다만 **한 문장 안에 두 격을 섞지 않는다.**

## 1.1 EN — 원본 규칙

영문이 원본이므로 여기서 잘못 쓰면 4개 언어가 함께 무너진다.

### 문장

- **현재 시제 · 능동태**로 쓴다. 미래 시제를 남발하지 않는다.
- **2인칭**으로 사용자에게 말한다. 회사를 주어로 세우지 않는다.
- 한 문장 **20단어 이내**. 넘으면 자른다.
- 축약형(`don't` · `you'll` · `can't`)은 UI·FAQ에서 허용한다. 약관·법적 고지에서는 쓰지 않는다.

```
❌ Your license will be activated once payment has been processed by our system.
✅ Your license activates as soon as payment clears.

❌ We will send you an email.
✅ You'll get an email.
```

### 대소문자

| 대상 | 규칙 | 예 |
|---|---|---|
| 버튼 · CTA | **Title Case** | `Start Now` · `Cancel Subscription` |
| 페이지 · 섹션 제목 | **Title Case** | `Choose Your Plan` |
| 본문 · 에러 · 토스트 · 빈 상태 · 플레이스홀더 · 툴팁 | **Sentence case** | `Payment failed. Check your card details.` |

Title Case에서 전치사·관사·접속사(of · to · for · a · the · and)는 소문자로 둔다. 단 **첫 단어와 마지막 단어는 항상 대문자**다.

제품 용어는 문장 중간에서도 대문자를 유지한다 — Seat · Organization · SW Account · Team Console · Student Benefit.
일반 명사는 소문자다 — license · subscription · plan. 단 플랜 이름의 일부일 때는 대문자다 (`Enterprise Team`).

```
✅ Add Seats to your Organization.
✅ Your subscription renews on January 1, 2026.
❌ Add seats to your organization.
```

### 문장부호

| 대상 | 마침표 |
|---|---|
| 버튼, 레이블, 플레이스홀더, 제목 | 쓰지 않는다 |
| 본문, 에러, 토스트, 빈 상태 | 쓴다 (완전한 문장이므로) |

- 나열에는 **Oxford comma를 쓴다.** 번역 시 결합 관계가 흐려지는 것을 막는다 (`Maya, Houdini, and Unreal Engine`)
- 느낌표를 쓰지 않는다

### 이음표 금지 (2026-08-27 확정)

**문장 안에서 두 조각을 잇는 dash와 가운데 점을 쓰지 않는다.** 적용 범위는 사용자 노출 문구뿐 아니라 **우리가 생성하는 모든 글**이다. Figma Description, Spec Doc, 정책 문서, 티켓, 보드 파일, 채팅 보고 전부 포함한다.

| 금지 | 예 |
|---|---|
| em dash (`—`) | `카드 2개 — Annual, Monthly` |
| hyphen을 이음표로 (`-`) | `카드 2개 - Annual, Monthly` |
| 가운데 점 나열 (`·`) | `Individual · Student` |

설명이 필요하면 **콜론 구조**를 쓴다. 두 형태 중 하나다.

```
설명 대상: 설명
```

```
설명 대상:
설명
```

나열은 쉼표를 쓴다.

```
❌ 개인 계열은 단일 화면 — Step 분리 없음
✅ 개인 계열은 단일 화면: Step 분리 없음

❌ Monthly 카드 1개만 노출 — Student는 Annual 옵션 없음
✅ Monthly 카드 1개만 노출: Student는 Annual 옵션 없음

❌ *(정책 확인 필요 — 검증 시점 미정)*
✅ *(정책 확인 필요: 검증 시점 미정)*

❌ Individual · Student · Indie
✅ Individual, Student, Indie
```

앞말이 이미 콜론을 쓰고 있으면 줄을 나눈다.

```
❌ 클릭 시: 결제 요청 — 성공하면 주문 완료로 이동
✅ 클릭 시: 결제 요청
     성공: 주문 완료 화면으로 이동
```

**불릿 마커 `- `는 이 금지에 해당하지 않는다.** 구조 표기이며, 금지 대상은 문장 안의 이음표다. 줄표를 범위 표기(`5-10자`)나 고유명사(`CLO-SET`)에 쓰는 것도 해당하지 않는다.

### 번역을 견디는 영어

원문 영어가 번역 친화적이지 않으면 KO·ZH-CN·JA가 전부 어색해진다.

| 피할 것 | 이유 | 대신 |
|---|---|---|
| 명사 3개 이상 연속 | 수식 관계가 번역에서 무너진다 | `license assignment status` → `status of the assigned license` |
| 지시대명사 `it` · `this` · `that` 단독 | 가리키는 대상이 언어마다 달라진다 | 대상을 이름으로 다시 쓴다 |
| 관용구 · 은유 · 말장난 | 직역하면 뜻이 사라진다 | 직설적으로 쓴다 |
| 뜻이 particle에 실린 구동사 | `turn off` vs `turn down` 구분이 번역에서 사라진다 | `disable` · `reduce` |
| 조건절 중첩 | 어순이 다른 언어에서 해석이 갈린다 | 문장을 나눈다 |

```
❌ If you haven't set it up yet, you'll need to do that before it can be assigned.
✅ Create an SW Account first. You can then assign a license to it.
```

### 숫자 · 날짜

- UI의 수량은 **숫자로** 쓴다 — `1 Seat` (`one Seat` 아님)
- 날짜는 **월을 단어로** 쓴다. 숫자 날짜(`01/02/2026`, `2026.01.02`)는 국가마다 다르게 읽혀 금지
- 월은 **3글자 축약이 기본**이다: `Nov 26, 2026` (2026-09-03 확정. 월 3글자, 일, 쉼표, 연도 순)

### 금액 (2026-08-26 확정)

**통화 기호를 쓰지 않는다. 금액 뒤에 통화 코드를 붙인다.**

```
✅ 39 USD      2,000 USD      3.36 USD      8.25 USD/month
❌ $39.00      $2,000         $3.36         $8.25/month
```

`$`는 USD, CAD, AUD, SGD가 모두 같은 기호를 쓰기 때문에 글로벌 제품에서 어느 통화인지 알 수 없다. 코드를 붙이면 다통화로 확장할 때 표기를 바꾸지 않아도 된다.

| 항목 | 규칙 |
|---|---|
| 소수 자릿수 | 통화의 minor unit을 따른다. USD와 EUR은 2자리, **JPY와 KRW은 0자리**다. `4,300 JPY`에 소수점을 붙이지 않는다 |
| 정수 금액 | 소수점을 채우지 않는다: `39 USD` (`39.00 USD` 아님) |
| 천 단위 | 쉼표로 구분한다: `20,000 USD` |
| 주기 병기 | 슬래시 뒤에 소문자로 쓴다: `39 USD/month`. `/Month` 처럼 대문자로 쓰지 않는다 |
| 반올림 | 항목별로 하지 않는다. 세액은 세금 엔진 응답을 그대로 표시하고, 직접 계산하는 경우만 총계에서 한 번 half-up |
| 월 환산 표시 | 2자리까지 쓰고 **실제 청구액을 병기한다.** `23.33 USD/month`만 쓰면 12개월 곱셈이 연 청구액과 어긋난다 |
| 0원 | `0 USD`. 무료 기간이라는 뜻을 담지 않는다 |

내부 저장은 **최소 통화 단위 정수**로 한다 (USD는 센트, JPY는 엔). 부동소수점으로 금액을 계산하지 않는다.

## 1.2 KO — 정하는 것은 종결어미가 아니라 격(格)이다

**KO 본문의 격은 합니다체로 고정한다.** 그 안에서 종결어미는 문맥에 맞게 고른다. 어미를 하나하나 규격으로 묶지 않는다 — 같은 종결이 연달아 나오면 오히려 기계가 쓴 글처럼 읽힌다.

같은 격 안에서 쓸 수 있는 것들:

```
~합니다 · ~됩니다 · ~입니다 · ~할 수 있습니다 · ~하지 않습니다
~해 주세요            (요청 — ~해 주십시오는 과하고 ~하세요는 명령조)
~하시겠습니까? · ~할까요?   (확인 질문 — 상황에 맞는 쪽)
```

```
❌ 결제를 확인합니다. 라이선스를 발급합니다. 이메일을 발송합니다.
✅ 결제를 확인하고 있습니다. 완료되면 라이선스가 발급되고, 안내 메일을 보내드립니다.
```

**고정된 경계는 두 가지뿐이다.**

| 경계 | 이유 |
|---|---|
| `~해요` 체 금지 | 전문가용 프로덕션 툴의 목소리가 아니다 |
| 명령조(`~하세요` · `~하십시오`) 금지 | 사용자에게 지시하지 않는다 |

```
❌ 저장됐어요.              ✅ 저장했습니다.
❌ 라이선스가 없어요.        ✅ 보유한 라이선스가 없습니다.
❌ 카드 정보를 확인하세요.    ✅ 카드 정보를 확인해 주세요.
```

## 2. 작성 원칙

우리 제품의 조건에서 나온 원칙이다. 순서대로 점검한다.

### P1. 결과를 먼저 말한다

전문가는 과정 설명을 기다리지 않는다. 무슨 일이 일어났는지 · 일어날 것인지를 첫 문장에 둔다.

```
❌ 요청하신 내용을 처리하기 위해 결제 정보를 확인하는 중이며, 완료되면 라이선스가 발급됩니다.
✅ 결제를 확인하고 있습니다. 완료되면 라이선스가 즉시 발급됩니다.
```

### P2. 도메인 지식은 가정하고, 제품 지식은 가정하지 않는다

두 종류의 용어를 구분해서 다룬다.

| 종류 | 예 | 처리 |
|---|---|---|
| **도메인 용어** — 업계에서 이미 쓰는 말 | 패턴 · 시뮬레이션 · 리토폴로지 · 리깅 · Alembic · Concurrent Users | 설명하지 않는다 |
| **제품 용어** — 우리가 만든 말 | Seat · Organization · SW Account · Team Console · Student Benefit | 처음 만나는 자리에서 한 번 설명한다 |

```
❌ 동시에 프로그램을 사용할 수 있는 사람 수(자리 수)     ← 도메인 용어를 풀어 씀
✅ Concurrent Users

❌ SW Account를 선택해 주세요                          ← 제품 용어를 설명 없이 던짐
✅ 라이선스를 배정할 SW Account를 선택해 주세요. SW Account는 라이선스 할당 전용 계정입니다.
```

한 번 설명한 뒤에는 반복하지 않는다. 같은 화면에서 두 번 설명하는 것은 P4 위반이다.

### P3. 되돌릴 수 없으면 영향 범위를 밝힌다

라이선스·구독·Seat 관련 동작은 한 사람이 아니라 팀 전체의 작업 가능 여부를 바꾼다. 누가 영향을 받는지 쓴다.

```
❌ 정말 삭제하시겠습니까?
✅ 이 SW Account를 삭제하면 배정된 라이선스가 회수되고, 현재 사용 중인 팀원은 즉시 접속할 수 없게 됩니다.
```

### P4. 빼도 되는 말은 뺀다

`혹시` · `해당` · `정말` · `바로` · `보다 나은` · `손쉽게`는 대부분 지워도 뜻이 같다. 지운다.

같은 내용을 한 화면에서 두 번 말하지 않는다. 제목이 말한 것을 본문이 다시 말하지 않는다.

### P5. 번역을 견디게 쓴다

모든 문구는 4개 언어로 번역된다. 관용구 · 말장난 · 문화 의존 표현은 번역에서 무너진다.

```
❌ 준비 끝! 이제 달려볼까요?
✅ 설정을 완료했습니다.
```

### P6. 겁주지 않고, 숨기지도 않는다

구매를 유도하려고 불안을 만들지 않는다. 동시에 제약을 감추지도 않는다. 제약은 사용자가 결정하기 **전에** 알려준다.

```
❌ 지금 놓치면 다시 없는 기회입니다.
❌ (Student 4년 제한을 구매 후에야 안내)
✅ Student 플랜은 최초 인증일부터 4년간 이용할 수 있습니다.
```

### P7. 사과하지 않고 해결한다

`죄송합니다` · `불편을 드려`는 쓰지 않는다. 무엇이 잘못됐고 무엇을 하면 되는지만 쓴다.

```
❌ 불편을 드려 죄송합니다. 오류가 발생했습니다.
✅ 결제에 실패했습니다. 카드 정보를 확인해 주세요.
```

### 3.1 명사형 종결

마케팅 카피는 읽는 글이 아니라 **스캔하는 글**이다. 종결어미가 붙으면 리듬이 끊긴다.

| 금지 | 이유 |
|---|---|
| `~한다` | 딱딱한 서술체 |
| `~합니다` · `~됩니다` · `~입니다` | 본문 말투 — 카피에 부적합 |
| `~그게 전부` · `~바로` 류 수사적 마무리 | 진부한 클리셰 |

쓰는 방식:

- **명사형 종결** — 문장을 명사 또는 명사구로 끝낸다
- **동사 생략형** — 서술어 없이 마무리 (`~으로.` `~까지.` `~대로.` `~없이.`)
- **쉼표 호흡** — 긴 문장은 쉼표로 끊어 리듬을 만든다
- **나열형** — 기술 스펙은 쉼표로 나열 (`FBX, Alembic, OBJ`)

### 3.2 레퍼런스 예시 (변경 불가)

```
실제 봉제 패턴을 배치하고, 봉제선으로 연결.
현실의 재단 방식을 그대로 옮긴 워크플로우.

소재별 무게, 탄성, 마찰 계수 설정으로 각 소재 고유의 텍스처와 움직임 구현.
천의 성질, 중력, 마찰까지 의도한 대로.

리깅된 아바타를 불러오면 골격과 포즈에 맞게 자동 피팅.
다양한 체형과 포즈에서 안정적으로.

캐릭터의 움직임에 맞게 천의 물리 반응을 매 프레임 계산, 시뮬레이션 캐시로 저장.
자연스러운 주름과 흐름이 자동으로.

FBX, Alembic, OBJ 포맷으로 내보내 Maya, Houdini, Unreal Engine, Unity와 직접 연동.
기존 파이프라인 변경 없이.
```

### 3.3 구체적 기능 묘사 필수

추상적 감성 카피를 쓰지 않는다. MD가 실제로 **무엇을 구현하는지** 기술 언어로 쓴다.

```
❌ 소재마다 반응이 다르다
✅ 소재별 무게, 탄성, 마찰 계수 설정으로 각 소재 고유의 텍스처와 움직임 구현
```

### 3.4 결과 언어 우선

기술 설명보다 사용자가 얻는 결과를 앞세운다.

```
❌ 물리 엔진이 시뮬레이션을 처리합니다
✅ 자연스러운 주름과 흐름이 자동으로
```

- 짧고 선언적. 10단어 이내

## 4. 버튼 텍스트 ★

### 4.1 EN — Title Case 명사구

```
✅ Start Now · Get Verified · Contact Sales · Cancel Subscription · Add Seats
❌ Start now · GET VERIFIED · Click here to start
```

전치사·관사(of · to · for · a · the)는 소문자로 둔다. 단, 첫 단어는 대문자다.

### 4.2 KO — "하다" 동사에 `하기`를 붙이지 않는다

`저장`은 그 자체로 명사다. `저장하기`는 명사를 동사로 만들었다 다시 명사로 되돌린 중복이다.
화면에 `~하기`가 도배되면 버튼마다 같은 꼬리가 붙어 스캔이 안 된다.

```
❌ 저장하기 · 결제하기 · 삭제하기 · 적용하기 · 배정하기 · 계속하기
✅ 저장   · 결제   · 삭제   · 적용   · 배정   · 다음
```

**예외 — 순우리말 동사는 `-기`가 명사형이므로 유지한다.**

```
✅ 닫기 · 열기 · 건너뛰기 · 다시 시도 · 뒤로
```

판별법: `하기`를 떼도 말이 되면 뗀다. `저장하기`→`저장` ✅ / `닫하기` ✖ → `닫기` 유지.

### 4.3 목적어가 필요한 동작은 목적어를 붙인다

```
❌ Delete · Cancel · Remove            ❌ 삭제 · 취소 · 해제
✅ Delete Account · Cancel Subscription  ✅ 계정 삭제 · 구독 취소
```

### 4.4 `Confirm` · `확인` · `OK` 단독 금지 — 액션 에코

확인 다이얼로그의 실행 버튼은 **실제로 일어날 동작을 그대로** 쓴다.

```
❌ "구독을 취소하시겠습니까?" → [취소] [확인]
✅ "구독을 취소하시겠습니까?" → [닫기] [구독 취소]
```

다이얼로그 왼쪽(흐름 중단) 버튼은 항상 `Close` · `닫기`다. `취소`는 쓰지 않는다 — "구독 취소"와 "취소(닫기)"가 한 화면에서 충돌한다.

## 6. 금지 표현

### EN

| 금지 | 이유 |
|---|---|
| `Kindly` · `Simply` · `Just` · `With ease` | 난이도를 대신 판단한다 |
| `Please` 남용 | 매 문장마다 붙이지 않는다 |
| `You will be able to` | → `You can` |
| `Proceed to` | → `Go to` · 구체적 동사 |
| `Successfully` | 결과 자체가 성공을 말한다 |
| `Oops` · `Sorry` · 느낌표 | 전문가용 제품의 목소리가 아니다 |
| `Click here` | 링크 텍스트가 목적지를 말해야 한다 |

| `~하시기 바랍니다` | `~해 주세요` |
