화면 캡처를 보고 Figma Description Panel용 UX 스펙을 작성한다.

## 역할

첨부한 스크린샷을 분석해 `~/.claude/rules/figma-description.md` 기준으로
복붙 즉시 사용 가능한 Description 마크다운을 출력한다.

**필수 참조**: `~/.claude/rules/figma-description.md` 섹션 1~4 (계층 구조 + 판단 기준 + Header Note + 불릿 원칙)

---

## Phase 1 — 컴포넌트 식별 (구조 잠금)

스크린샷에서 모든 UI 요소를 나열하고, 각 요소에 Q1~Q3을 적용해 L1/L2를 분류한다.

### Q1~Q3 판단 기준

```
Q1. 시각적으로 독립된 영역을 차지하는가? (카드, 섹션, 배너, 모달, 탭 등)
Q2. 자체 상태를 가지는가? (Default / Hover / Active / Disabled / Loading / Error 등)
Q3. 사용자 인터랙션이 있는가? (클릭 / 호버 / 입력 등 → 결과 발생)

하나라도 YES → L1 (Numbered Note)
전부 NO → L2 (불릿)
```

### 출력 형식

```
| 요소 | Q1 독립영역 | Q2 자체상태 | Q3 인터랙션 | 결과 |
|---|---|---|---|---|
| Plan Badge | X | O | X | **L1** |
| CTA Button | X | O | O | **L1** |
| Plan Name 텍스트 | X | X | X | L2 |
| ... | ... | ... | ... | ... |
```

- **부모-자식 관계 → 평탄화**: 카드 안 버튼은 둘 다 L1으로 분리
- **콜론 판별법**: `요소명: 설명` 패턴이 보이면 L1 분리 검토

---

## Phase 2 — 골격 생성

Phase 1 결과로 Description 골격을 확정한다. 이 시점에서 구조가 잠긴다.

```
**[화면명]**                    ← L0: 한 줄만, 불릿 금지

**① [L1 요소 A]**              ← L1: 빈 Note
**② [L1 요소 B]**              ← L1: 빈 Note
**③ [L1 요소 C]**              ← L1: 빈 Note
...
```

### 골격 규칙
- L0 (Header Note) = `**[화면명]**` 한 줄만. 불릿·컨텍스트·접근조건 절대 금지.
- 컨텍스트 필요 시 → `**① Page Context**` Note로 분리
- COMMON 참조 → 별도 Numbered Note (`**① GNB** → COMMON 참조`)
- L2 요소는 골격에 포함하지 않음 — Phase 3에서 소속 L1 아래에 불릿으로 작성

---

## Phase 3 — 내용 채우기

각 L1 Note에 L2 불릿을 작성한다.

### 블록 순서 (고정, 변경 금지)

```
기본 동작 → 상태 → 트리거(클릭/체크 시 + 성공/실패) → 비즈니스 로직 → 조건부 노출 → 옵션
```

### 쓰는 것 / 안 쓰는 것

| 쓴다 (화면에서 안 보이는 것) | 안 쓴다 (화면에서 보이는 것) |
|---|---|
| 동작 (클릭 시 결과) | 버튼 레이블 텍스트 |
| 상태 변화 | 요소의 위치 ("하단에 위치") |
| 조건 (언제 표시/숨김) | 색상, 크기, 폰트 |
| 비즈니스 로직 (IF/ELSE) | 화면에 적힌 안내 문구 그대로 |
| 에러 처리 | "~라고 적힌 버튼" |
| 연결 (어디로 이동) | 디자인 스펙 (px, hex) |

### 1불릿 = 1사실

```
❌ "구독 중일 때 표시되며 클릭 시 Pause 모달을 엶"
✅ "구독 중일 때 표시"
   "클릭 시: Pause 모달 오픈"
```

### 카테고리 레이블 필수

L3 서브불릿은 반드시 카테고리 레이블 뒤에 온다: `상태:` / `옵션:` / `조건부 노출:` / `비즈니스 로직:`

### 인터랙션 불릿 고정 구조

```
- [트리거] 시: [동작]
  - 성공: [결과]
  - 실패: [에러 처리]
```

성공 후 조건 분기 → 비즈니스 로직으로 분리:
```
- 클릭 시: 결제 요청
  - 성공: 비즈니스 로직 참조
  - 실패: 에러 토스트
- 비즈니스 로직:
  - IF [조건 A] → [처리]
  - ELSE → [처리]
```

### 상태 블록 필수 항목

- Loading: API 호출이 있는 컴포넌트 — 필수
- Empty: 데이터 표시 컴포넌트 — 필수
- Error: 서버/네트워크 실패 — 필수
- 상태 순서: Active → Trial → Pause Scheduled → Paused → Cancel Scheduled → Cancelled → Expired

### 작성 원칙

- 단문 원칙: 1줄 = 1행동 or 1규칙. 주어 생략.
- 명사형 종결: `~노출` / `~비활성화` / `~이동` / `~닫힘` / `~전환`
- 기술 스펙 금지: px, hex, CSS 값 절대 포함 안 함
- 서술체 금지: `~입니다` / `~합니다` 사용 금지
- 불확실 항목: *(정책 확인 필요)* / *(개발 확인 필요)* / *(협의 필요)*

---

## Phase 4 — QA 체크 + 출력

출력 전 자체 검증. 이탈 항목 있으면 수정 후 출력.

### 계층 구조
- [ ] Header Note(L0)가 화면명 한 줄만인가? (불릿 없음 — 패턴 5)
- [ ] 모든 독립 UI 요소가 Numbered Note(L1)로 분리됐는가? (패턴 4)
- [ ] L2 불릿에 `요소명: 설명` 패턴이 없는가?
- [ ] L2 불릿 1개에 사실 1개만 담겨 있는가?
- [ ] L3 서브불릿 위에 카테고리 레이블이 있는가?
- [ ] L3 아래에 추가 중첩(L4)이 없는가?

### 상태·포맷
- [ ] 상태가 라이프사이클 순서대로 나열됐는가?
- [ ] API 연동 컴포넌트에 Loading/Empty/Error가 있는가?
- [ ] 성공 후 분기가 비즈니스 로직 블록으로 분리됐는가? (패턴 1)
- [ ] 에러 동작이 상태: Error: 블록 안에 있는가? (패턴 2)
- [ ] 미완성 문장이나 메모가 섞이지 않았는가? (패턴 3)
- [ ] 컴포넌트가 불릿으로 나열되지 않았는가? (패턴 4)
- [ ] Header Note에 불릿이 없는가? (패턴 5)

---

## 출력 형식

코드 블록 없이 **마크다운 원문 그대로** 출력한다 (복붙 즉시 사용 가능).

스크린샷에서 판단 불가한 항목(API 연동 여부, MemberType 분기 등)은
`*(개발 확인 필요)*` 또는 `*(정책 확인 필요)*`로 표시하고 계속 진행한다.
