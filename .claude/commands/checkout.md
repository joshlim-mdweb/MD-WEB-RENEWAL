# checkout

세션 마감 루틴. /initiate의 반대. 프로젝트 파일을 갱신하고 실수 노트를 기록한다.

**왜 필요한가:** Claude는 세션이 끝나면 기억을 잃는다. 프로젝트 단위로 TODO와 컨텍스트를 저장해두면 다음 세션에서 어느 Claude든 바로 이어받을 수 있다.

---

## Step 0 — 프로젝트 확인

`docs/backlog/projects/` 디렉토리를 읽어 기존 프로젝트 파일 목록을 파악한다.

사용자에게 묻는다:

> "어떤 프로젝트로 저장할까요? (기존: {파일 목록} / 새 이름 입력 가능)"

- 기존 프로젝트 선택 시 → 해당 파일 업데이트
- 새 이름 입력 시 → `docs/backlog/projects/{name}.md` 신규 생성
- `docs/backlog/projects/` 디렉토리가 없으면 자동 생성

### 프로젝트 이름 규칙 (새 이름 입력 시 안내)

| 규칙 | 예시 |
|------|------|
| kebab-case, 영문 소문자 | `student-plan-renew` ✅ / `StudentPlan` ❌ |
| 기능·작업 영역 중심으로 — Jira Epic 이름과 맞출 것 | `checkout-flow`, `gnb-renewal` |
| 내부 툴·워크플로우 작업은 `claude-` prefix | `claude-workflow`, `claude-rules` |
| 너무 짧거나 모호한 이름 금지 | `test`, `work`, `temp` ❌ |
| 최대 30자 이내 | |

새 이름을 받으면 위 규칙 기준으로 문제가 있을 경우 한 줄로 지적하고 대안을 제시한다. 사용자가 그대로 쓰겠다고 하면 따른다.

---

## Step 1 — 프로젝트 파일 갱신

세션에서 다룬 내용을 정리해 프로젝트 파일을 **덮어쓴다** (append가 아닌 전체 갱신).

### 수집할 내용

1. 세션에서 나눈 대화 기반으로 완료된 항목·미결 항목 정리
2. 관련 Jira 티켓 목록 파악
3. 다음에 이어받을 사람이 바로 시작할 수 있는 컨텍스트 정리

### 저장 포맷

```markdown
---
project: {프로젝트 이름}
updated: {YYYY-MM-DD}
---

## 관련 Jira 티켓
- MDWEB-{id} — {제목} ({상태})

## TODO
1. {다음에 할 것 — 구체적 액션으로, 우선순위순}
2. {두 번째}
3. ...

## 컨텍스트
- {내린 결정과 이유}
- {미결 항목과 현재 상태}
- {블로커 또는 기다리는 것}

## 완료 로그
### {YYYY-MM-DD}
- {오늘 완료한 항목}
- {오늘 완료한 항목}
```

**완료 로그 규칙:**
- 기존 완료 로그는 유지하고 오늘 날짜 항목을 **맨 위에 추가**한다.
- TODO와 컨텍스트는 항상 최신 상태로 전체 교체한다.

---

## Step 2 — 실수 노트

사용자에게 묻지 않는다. **세션 대화를 직접 분석해** Claude가 자동으로 작성한다.

### 기록 대상

다음 중 하나라도 해당하면 기록한다:

- 사용자가 수정을 요구했거나 지적한 것 ("이건 아닌 것 같아", "아니 그게 아니라", "다시 해줘" 등)
- Claude가 잘못된 방향으로 진행하다 우회한 것 (파일 못 찾음, 툴 실패 후 재시도, 잘못된 가정 등)
- 같은 실수를 두 번 이상 반복한 것

해당 사항 없으면 Step 2 전체 스킵.

`docs/backlog/mistakes.md`가 없으면 헤더와 함께 새로 생성한다.

### 실수 노트 포맷 (append)

```markdown
## {YYYY-MM-DD}

**상황:** {어떤 작업 중에 발생했는지}
**실수:** {뭘 잘못했는지}
**원인:** {왜 그렇게 됐는지 — 짧게}
**다음엔:** {어떻게 피할지 — 구체적 행동}
```

여러 개면 같은 날짜 헤더 아래에 `---`로 구분해 이어 쓴다.

## Step 3 — 상태 리포트

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
🏁 세션 마감 — {날짜}
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

저장된 프로젝트
  docs/backlog/projects/{name}.md   ✅
  docs/backlog/mistakes.md          ✅ / ⏭ 스킵

다음 TODO 1순위
  → {TODO 첫 번째 항목}

━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

---

## 규칙

- Step 0은 항상 사용자에게 프로젝트를 확인한다 — 추측해서 고르지 않는다
- Step 1은 항상 실행 (사용자 입력 없이 자동 저장)
- Step 2는 Claude가 세션 대화를 분석해 자동 작성 — 사용자에게 묻지 않는다
- 저장 후 파일 경로를 출력한다 (사용자가 확인할 수 있도록)
